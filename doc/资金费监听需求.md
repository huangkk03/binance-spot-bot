# 📄 需求规格说明书（SRS）：币安合约资金费率现货抄底提醒功能扩展

## 1. 变更背景与目标
### 1.1 背景
当前系统已具备完整的 Vue + Spring Boot 基础架构与企业微信（WeChat Work）通知链路。为了优化现货交易的抄底时机选择，需要引入币安（Binance）永续合约的**资金费率（Funding Rate）**作为量化辅助指标。
### 1.2 目标
在**不改变现有数据库结构、不新增前端 Vue 交互、不涉及自动挂单交易**的前提下，纯粹通过后端 Spring Boot 增量开发一个定时任务。当指定币种的合约资金费率出现极端负值（空头拥挤）时，通过现有的企业微信机器人通道推送标准格式的 Markdown 抄底预警消息。

---

## 2. 业务流程与逻辑架构
[ 币安 API (Premium Index) ]
│ (每5分钟 HTTP GET 轮询)
▼
[ Spring Boot 定时任务调度 ] ──(过滤非监听币种)──> [ 触发器逻辑校验 ]
│
(校验负费率阈值与2小时冷却)
│
▼
[ 企业微信机器人 Webhook ] <──(发送 Markdown 消息)── [ 消息组装服务 ]

---

## 3. 功能详细需求

### 3.1 币安行情数据采集（后端增量）
* **执行周期：** 每 5 分钟执行一次（支持配置化或默认 `300,000ms` 固定频率）。
* **接口端点：** `GET https://fapi.binance.com/fapi/v1/premiumIndex`（公共接口，无需 API Key 鉴权）。
* **监听目标：** 系统内设核心资产监听列表。

### 3.2 信号过滤与判定算法
系统获取到网关数据后，需将 `lastFundingRate` 转换为百分比形式（例如：`-0.0025` 转换为 `-0.25%`），并根据币种属性匹配两级触发阈值：

| 资产类别 | 覆盖币种 | 🚨 级别一：【预警信号】阈值 | 💥 级别二：【绝对信号】阈值 |
| :--- | :--- | :--- | :--- |
| **主流资产 (Main)** | `BTCUSDT`, `ETHUSDT` | 资金费率 ≤ -0.05% | 资金费率 ≤ -0.10% |
| **山寨资产 (Alt)** | 其他所有指定监听币种 | 资金费率 ≤ -0.10% | 资金费率 ≤ -0.20% |

### 3.3 频率限制机制（防轰炸）
* **控制策略：** 采用内存缓存（如 `ConcurrentHashMap`）维护状态机。
* **冷却规则：** **同一币种在同一信号级别下，2小时内仅允许成功推送一次。**
* **熔断覆盖：** 若当前币种信号从【级别一】升级为【级别二】，则无视 2 小时冷却限制，必须立即触发最新级别的推送。

### 3.4 消息组装与企业微信推送
当触发算法判定通过时，系统需动态计算**年化费率**（公式：`当前费率 * 3 * 365`）与**结算倒计时**，并组装为标准的 Webhook Markdown 格式发送至企业微信。

* **消息文本规范：**
```markdown
🟢 **【币安现货抄底提醒】—— 发现轧空信号！**
> **监控币种：** `[动态币种，如 SOLUSDT]`
> **信号级别：** `[💥 级别二：【绝对信号】（空头极度拥挤） / 🚨 级别一：【预警信号】]`
> **当前资金费率：** `[动态费率，如 -0.2450%]`（年化约 `[动态年化，如 -268.28%]`）
> **下次结算时间：** 还有 `[动态倒计时，如 02小时15分钟]`
> **持仓量(OI)状态：** `已达监控阈值` 📈

4. 接口与数据交互规范
4.1 币安输入数据结构（JSON 关键字段）
[
  {
    "symbol": "SOLUSDT",
    "lastFundingRate": "-0.00245000", 
    "nextFundingTime": 1774224000000  
  }
]
4.2 企业微信输出数据结构（应用层协议）
请求方式： POST

Content-Type： application/json

Payload 结构：
{
  "msgtype": "markdown",
  "markdown": {
    "content": "🟢 **【币安现货抄底提醒】—— 发现轧空信号！**\n..."
  }
}

5. 非功能性需求与异常处理
网络容错： 请求币安网关若发生超时（Timeout）或 5xx 异常，系统需捕获异常并记录低级别日志，禁止阻断主线程，等待下一个周期自动重试。

时钟同步： 结算倒计时计算需采用服务器本地系统时间戳（System.currentTimeMillis()）与币安返回的 nextFundingTime 进行差值计算，确保差值绝对值合法。

低耦合性： 该模块的所有组件需声明在独立的 package 下（如 com.xxx.modules.binance），确保可随时整体下线或一键注释。
